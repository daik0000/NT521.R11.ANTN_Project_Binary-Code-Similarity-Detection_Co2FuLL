- `fflush(stdout/stderr)` → đồng bộ các stream.

## Target 2 — `sub_18860`

### High-level code

```c
unsigned int scan_format(const char *format, TypeInfo *types)
{
    unsigned int argument_count = 0;

    for (const char *p = format; *p != 0; p = next_conversion(p)) {
        parse_flags_width_precision_and_length(p);
        types[argument_count] = identify_conversion_type(p);
        ++argument_count;
    }

    return argument_count;
}
```

Hàm chỉ scan format string, ghi kiểu của các conversion vào bảng và trả về số
đối số/conversion đã phát hiện; không đọc đối số thực tế và không ghi output.

### Mapping

- `a1` → format string.
- `a2` → bảng `TypeInfo`.
- Các bước parse → flags, width, precision, length modifier và conversion.
- Giá trị trả về → số conversion/đối số đã phát hiện.

## Vì sao BCSD là NO

Hai hàm có chung một phase phân tích format string, nhưng Target 1 là error
handler hoàn chỉnh còn Target 2 chỉ là scanner. Input phụ, output, giá trị trả
về và side effect khác nhau; việc cùng có các keyword về format không đủ chứng
minh hai hàm được biên dịch từ cùng source.

## Giải thích lỗi của LLM

LLM chỉ dựa vào phần format parsing và việc xuất kết quả mà không phân biệt
Target 2 không có `FILE *`, không load `va_list` và không gọi các hàm output.
