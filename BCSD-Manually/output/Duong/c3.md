# Đánh giá BCSD — Dương/c3

**Kết luận:** `YES`

## High-level code tương ứng

```c
float parse_and_validate_float(const char *text,
                               float min_value, float max_value,
                               const char *unit, int mode)
{
    float value;
    char suffix[256];

    int fields = sscanf(text, "%f%255s", &value, suffix);
    if (fields == 2)
        value *= unit_scale(suffix);
    else if (fields != 1)
        report_invalid_argument(text);

    value /= unit_scale(unit);

    if (!is_valid_range(value, min_value, max_value, mode))
        report_invalid_argument(text);

    return value;
}
```

Hàm phân tích một số thực từ chuỗi, tùy chọn nhận hậu tố đơn vị. Nếu có hậu tố,
giá trị được đổi sang đơn vị nội bộ; sau đó giá trị được chuẩn hóa theo `unit`
đích. `mode` chọn một trong các điều kiện biên: không kiểm tra, cận dưới/cận
trên, hoặc các khoảng đóng/mở khác nhau. Đầu vào sai định dạng hay nằm ngoài
khoảng hợp lệ sẽ in thông báo lỗi và kết thúc; đầu vào hợp lệ trả về số đã đổi
đơn vị.

## Khác biệt nhỏ

Hai target có cùng tham số và cùng các điều kiện mode. Target 1 dùng các helper
`sub_8078A30`, bảng đơn vị `dword_8094368` và địa chỉ global tương ứng; target 2
dùng `sub_80774C0`, bảng `dword_809236C`. Compiler cũng sinh control-flow khác
nhau: target 1 dùng nhiều nhánh `goto`, target 2 gom một số nhánh qua biến
format. Các biểu thức tương đương, chẳng hạn điều kiện hợp lệ `min < value <
max` ở target 2 tương ứng với phủ định điều kiện lỗi ở target 1.
