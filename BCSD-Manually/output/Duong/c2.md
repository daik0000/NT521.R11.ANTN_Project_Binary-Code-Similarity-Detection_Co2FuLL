# Đánh giá BCSD — Dương/c2

**Kết luận:** `YES`

## High-level code tương ứng

```c
int visit_and_clear(Context *ctx, Visitor visitor)
{
    if (visitor != NULL) {
        for (unsigned int i = 0; i < ctx->count; ++i)
            visitor(ctx->items[i]);
    }

    ctx->count = 0;
    return ctx;
}
```

Hàm gọi `visitor` một lần cho từng phần tử hiện có (nếu callback tồn tại), sau
đó làm rỗng container bằng cách đặt số phần tử về 0. Nếu callback là `NULL`,
hàm vẫn xóa số phần tử nhưng không gọi callback.

## Mapping giữa hai target và high-level code

### Target 1 — `sub_66E08`

- `a1` → `ctx`.
- `a2` → `visitor`.
- `a2 != nullptr` → kiểm tra callback hợp lệ.
- `*(a1 + 20)` → `ctx->count`.
- `*(a1 + 24)` → `ctx->items`.
- `*(*(a1 + 24) + 4 * i)` → `ctx->items[i]`.
- `a2(ctx->items[i])` → `visitor(ctx->items[i])`.
- `*(a1 + 20) = 0` → `ctx->count = 0`.
- Giá trị trả về `a1` → `ctx`.

### Target 2 — `sub_5FF68`

- `result`/`v3` → `ctx`.
- `a2` → `visitor`.
- `*(v3 + 20)` → `ctx->count`; `*(v3 + 24)` → `ctx->items`.
- `*(*(v3 + 24) + 4 * i)` → `ctx->items[i]`.
- `a2(ctx->items[i])` → lời gọi visitor.
- `*(v3 + 20) = 0` → `ctx->count = 0`.

## Khác biệt nhỏ

Hai target đều duyệt callback rồi đặt `count` về 0. Target 1 khai báo callback
trả về `void` và luôn trả về context. Ở target 2, decompiler thể hiện callback
trả về `int` và gán kết quả đó vào `result`; vì vậy giá trị trả về cuối cùng có
thể là kết quả của lần gọi callback cuối. Đây là khác biệt ở kiểu/giá trị trả về,
không thay đổi logic duyệt và xóa container. Target 1 là ARM 32-bit, target 2
là ARM 32-bit nhưng được biên dịch bằng GCC khác; cả hai dùng cùng offset và
bước phần tử 4 byte.
