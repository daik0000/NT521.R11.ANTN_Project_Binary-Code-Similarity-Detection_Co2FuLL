# Đánh giá BCSD — Dương/c5

**Kết luận:** `YES`

## High-level code tương ứng

```c
int find_first(Context *ctx, Item key)
{
    for (unsigned int i = 0; i < ctx->count; ++i) {
        if (ctx->compare(ctx->items[i], key) == 0)
            return (int)i;
    }

    return -1;
}
```

Hàm tìm phần tử đầu tiên mà comparator trả về 0. Nó duyệt tuần tự từ chỉ số 0,
trả về chỉ số ngay khi tìm thấy; nếu container rỗng hoặc không có phần tử phù
hợp thì trả về `-1`.

## Mapping giữa hai target và high-level code

### Target 1 — `sub_807BE20`

- `a1` → `ctx`; `a2` → `key`.
- `*(a1 + 20)` → `ctx->count`.
- `*(a1 + 24)` → `ctx->items`.
- `*(a1 + 32)` → `ctx->compare`.
- `*(*(a1 + 24) + 4 * v2)` → `ctx->items[i]`.
- `(*(a1 + 32))(ctx->items[i], a2) != 0` → phần tử chưa khớp.
- `return v2` → chỉ số tìm thấy; các nhánh còn lại trả `-1`.

### Target 2 — `sub_40BF4`

- `a1` → `ctx`; `a2` → `key`; `v5` → `i`.
- Các offset `20`, `24`, `32` lần lượt → `count`, `items`, `compare`.
- `*(*(a1 + 24) + 4 * v5)` → `ctx->items[i]`.
- Vòng `while` và điều kiện `++v5 >= count` → tiếp tục tìm hoặc trả `-1`.
- `return v5` → chỉ số phần tử khớp.

## Khác biệt nhỏ

Target 1 khởi tạo chỉ số bằng 0 rồi xử lý trường hợp `count == 0` trước vòng
lặp; target 2 khởi tạo kết quả bằng `-1` và dùng nhánh sớm. Target 1 là x86
32-bit GCC, target 2 là ARM 32-bit Clang; layout context và bước phần tử đều
giống nhau, logic tìm kiếm tương đương.
