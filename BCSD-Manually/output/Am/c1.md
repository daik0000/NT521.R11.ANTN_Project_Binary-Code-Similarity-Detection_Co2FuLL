# Đánh giá BCSD — Âm/c1

**Kết luận:** `NO`

## Target 1 — `sub_804E3D0`

### High-level code

```c
bool check_all(Context *ctx, Checker checker)
{
    bool result = true;
    for (unsigned int i = 0; i < ctx->count; ++i)
        result = checker(ctx, ctx->items[i]) && result;
    return result;
}
```

Hàm gọi checker trên mọi phần tử và trả về phép AND của toàn bộ kết quả; container
rỗng trả về `true`.

### Mapping

- `a1` → `ctx`, `a2` → `checker`.
- `*(a1 + 20)` → `ctx->count`; `*(a1 + 24)` → `ctx->items`.
- `*(*(a1 + 24) + 4 * i)` → `ctx->items[i]`.
- `sub_804E490(a2, item)` và `LOBYTE(a3)` → lời gọi checker và kết quả tích lũy.

## Target 2 — `sub_80859A6`

### High-level code

```c
bool contexts_equal(Context *left, Context *right)
{
    if (left->count != right->count)
        return false;

    for (unsigned int i = 0; i < left->count; ++i) {
        if (left->compare(left->items[i], right->items[i]) != 0)
            return false;
    }

    return true;
}
```

Hàm trước hết so sánh số lượng phần tử của hai context. Sau đó nó so sánh từng
cặp phần tử tương ứng bằng comparator; chỉ khi mọi cặp bằng nhau mới trả về
`true`.

### Mapping

- `a1` → `left`; `a2` → `right`.
- `*(a1 + 20)` và `*(a2 + 20)` → `left->count` và `right->count`.
- `*(a1 + 24)`, `*(a2 + 24)` → hai mảng `items`.
- `*(a1 + 32)` → `left->compare`.
- `*(4 * i + *(a1 + 24))`, `*(4 * i + *(a2 + 24))` → hai phần tử ở chỉ số `i`.
- Comparator khác 0 → trả `false`; hết vòng lặp → trả `true`.

## Vì sao BCSD là NO

Target 1 thực hiện phép kiểm tra độc lập trên từng phần tử của **một** context
và AND các kết quả. Target 2 so sánh kích thước của **hai** context rồi so sánh
các cặp phần tử tương ứng. Target 2 không gọi một checker trên từng phần tử và
target 1 không có nhánh so sánh hai context, nên hai hàm không có cùng logic.
