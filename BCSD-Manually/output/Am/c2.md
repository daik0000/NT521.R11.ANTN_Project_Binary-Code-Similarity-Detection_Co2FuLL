# Đánh giá BCSD — Âm/c2

**Kết luận:** `NO`

## Target 1 — `sub_804E3D0`

### High-level code

```c
bool check_all(Context *ctx, Checker checker)
{
    bool result = true;
    for (unsigned int i = 0; i < ctx->count; ++i)
        result = checker(ctx, ctx->items[i]) && result;
    return result;
}
```

Hàm duyệt toàn bộ mảng và trả về `true` khi tất cả checker đều trả về khác 0.

### Mapping

- `a1` → `ctx`, `a2` → `checker`.
- Offset `20` → `count`; offset `24` → `items`.
- `*(*(a1 + 24) + 4 * i)` → `items[i]`.
- `sub_804E490(...) & a3` → phép AND tích lũy kết quả checker.

## Target 2 — `sub_4517A0`

### High-level code

```c
long find_first(Context *ctx, Item key)
{
    for (unsigned long i = 0; i < ctx->count; ++i) {
        if (ctx->compare(ctx->items[i], key) == 0)
            return (long)i;
    }
    return -1;
}
```

Hàm tìm phần tử đầu tiên mà comparator cho kết quả bằng 0 và trả về chỉ số của
phần tử đó. Nếu không tìm thấy, nó trả `-1`.

### Mapping

- `a1` → `ctx`; `a2` → `key`; `i` → chỉ số duyệt.
- `*(a1 + 40)` → `ctx->count`.
- `*(a1 + 48)` → `ctx->items`.
- `*(a1 + 64)` → `ctx->compare`.
- `*(*(a1 + 48) + 8 * i)` → `ctx->items[i]`.
- Comparator bằng 0 → trả `i`; hết vòng lặp → trả `-1`.

## Vì sao BCSD là NO

Target 1 là phép AND trên tất cả kết quả checker và trả về một giá trị Boolean.
Target 2 là phép tìm kiếm tuần tự, dừng ở phần tử đầu tiên khớp và trả về chỉ
số. Một hàm không có kết quả chỉ số hay điều kiện so sánh khóa, còn hàm kia
không có tích lũy Boolean, nên khác logic cốt lõi.
