# Đánh giá BCSD — Âm/c5

**Kết luận:** `NO`

## Target 1 — `sub_66E08`

### High-level code

```c
Context *visit_and_clear(Context *ctx, Visitor visitor)
{
    if (visitor != NULL) {
        for (unsigned int i = 0; i < ctx->count; ++i)
            visitor(ctx->items[i]);
    }

    ctx->count = 0;
    return ctx;
}
```

Hàm tùy chọn gọi visitor trên từng phần tử, sau đó xóa logic toàn bộ container
bằng cách đặt `count` về 0.

### Mapping

- `a1` → `ctx`; `a2` → `visitor`.
- `*(a1 + 20)` → `ctx->count`; `*(a1 + 24)` → `ctx->items`.
- `*(*(a1 + 24) + 4 * i)` → `ctx->items[i]`.
- `a2(...)` → `visitor(...)`.
- `*(a1 + 20) = 0` → `ctx->count = 0`.

## Target 2 — `rec_sex_ast_node_reset`

### High-level code

```c
AstNode *reset_ast(AstNode *node)
{
    for (unsigned int i = 0; i < node->child_count; ++i)
        reset_ast(node->children[i]);

    node->value = 0;
    return node;
}
```

Hàm reset AST theo kiểu hậu thứ tự: đệ quy reset toàn bộ node con trước, sau đó
đặt trường trạng thái/giá trị của node hiện tại về 0.

### Mapping

- `a1` → `node`.
- `*(a1 + 36)` → `node->child_count`.
- `*(a1 + 4 * i + 24)` → `node->children[i]`.
- `rec_sex_ast_node_reset(...)` → lời gọi đệ quy trên node con.
- `*(a1 + 12) = 0` → `node->value = 0`.
- `return a1` → trả lại node hiện tại.

## Vì sao BCSD là NO

Target 1 thực hiện callback tùy chọn trên một mảng phẳng rồi đặt số lượng phần
tử về 0. Target 2 duyệt cây AST đệ quy và reset trường dữ liệu của từng node;
nó không nhận visitor, không có mảng `items`, không thay đổi `child_count`. Cấu
trúc dữ liệu và hành vi chính khác nhau nên kết quả BCSD là `NO`.
